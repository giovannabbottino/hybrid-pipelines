Build structured RDF triples for the input text using the extracted entities and Wikidata evidence.

Input JSON:
${PAYLOAD}

Return exactly one JSON object with a non-empty `triples` array. Each item must contain:
- `subject`: `wd:Q...`, `kg:snake_case_name`, or another supported prefixed identifier
- `predicate`: `rdf:type`, `rdfs:label`, or a concise `kg:snake_case_name`
- `object`: a resource identifier or literal value
- `object_type`: exactly `resource` or `literal`
- optional `language` for literals, normally `en`
- optional `datatype` for typed literals, such as `xsd:date`

Rules:
- Return JSON only. Do not return Turtle, prefixes, Markdown, comments, or explanations.
- Preserve every `entities[].id` QID as the corresponding `wd:Q...` resource.
- Never invent, change, normalize, or omit a provided QID.
- Use each resolved resource in at least one semantic relationship triple.
- Materialize every provided relationship exactly once with its subject and object QIDs.
- Map `instance of` and `subclass of` to `kg:is`, `part of` to `kg:part_of`, and `has part`
  to `kg:has_part`.
- Convert every other property label to a concise snake_case `kg:` predicate.
- Add an `rdfs:label` literal with language `en` for every resource. Prefer `mention.surface`, then
  the entity or relationship label. Never use a QID as label text.
- Create additional relationships needed to cover the complete input passage, but do not add facts
  unrelated to the text or supplied relationships.
- Keep distinct QIDs as distinct resources.
- Set `object_type` to `resource` for identifiers and `literal` for literal values.
- A literal may contain `language` or `datatype`, but not both.
- Every triple must have a non-empty subject, predicate, object, and object_type.
